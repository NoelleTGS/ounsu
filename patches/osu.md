# osu! (`src/osu`)

Upstream: [ppy/osu](https://github.com/ppy/osu), base commit in `osu.base` (`169c020824`, tag `2026.1115.0-lazer`). Patch:
`osu.diff`. `src/osu` is the modified checkout the build uses.

Every change sits behind `#if OUNSU` (or one of the finer `OUNSU_*` defines), which `console/osu-game/build.sh` turns on with
`-p:OunsuBuild=true` (it must be on the dotnet command line, or it doesn't reach the referenced projects). A normal desktop build of this checkout is unchanged.

## NativeAOT

osu! uses reflection that NativeAOT can't serve, mostly generic code over value types created at runtime:

| File | Change |
|---|---|
| `Database/OunsuRealmCopier.cs` (new), `Database/RealmObjectExtensions.cs` | Detaching Realm objects without AutoMapper (it emits code at runtime). Copies the same members the AutoMapper configuration did |
| `Configuration/SettingSourceAttribute.cs` | Enum settings use a non-generic dropdown over boxed values (`MakeGenericType(ModSettingsEnumDropdown<TEnum>)` crashed the mod select overlay) |
| `Graphics/UserInterface/RollingCounter.cs` | No string-based `TransformTo` on value-type instantiations |
| `Utils/BindableValueAccessor.cs` | No `MakeGenericMethod` over value types |
| `osu.Game.csproj` | `OunsuBuild` / `OunsuDetachTest` build settings; `Directory.Build.targets` (new) is the version stamp below |

`console/osu-game/rd.xml` (generated by `tools/gen-rdxml`) covers the collection types Newtonsoft.Json creates by
reflection; that one lives in this repository, not in the patch.

## Console specifics

| File | Change |
|---|---|
| `IO/OunsuFileResourceStore.cs` (new), `OsuGameBase.cs` | Game resources are loose files on the SD card (`/switch/ounsu/osu-resources`, extracted on the PC with `tools/resource-extract`), not an embedded DLL |
| `Overlays/SettingsOverlay.cs` | `CreateExtraSections`: lets the console app add its "Switch 2" settings section (`console/osu-game/Switch2Settings.cs`). Behind `OUNSU_SETTINGS`, which the desktop test build (`OunsuDetachTest`) also defines |
| `Rulesets/UI/FrameStabilityContainer.cs` | Catch up after long pauses instead of the 500 ms guard (a long GC pause froze gameplay for good) |
| `Screens/Play/SubmittingPlayer.cs` | Playback-rate validation off (GC pauses made it report "check your audio drivers") |

## Version stamp

`Directory.Build.targets` (new) stamps osu.Game and the rulesets with the build date in osu!'s `yyyy.Mdd` scheme (for
example `2026.1109.0`), like ppy's release builds get from CI. Skin layouts name their component types with the version
that saved them (`osu.Game, Version=2026.807.0.0`), and .NET won't resolve a reference to a newer version than the loaded
assembly. Unstamped (0.0.0), every saved layout fell back to the defaults. The console entry assembly
(`console/osu-game`) stays 0.0.0, so osu! still treats the build as not deployed (see below).

## Online

| File | Change |
|---|---|
| `Online/API/APIAccess.cs` | `GetHubConnector` only makes the metadata hub's connector (`OUNSU_HUBS=0`: none). Spectator and multiplayer return null like the offline API does: ppy's server refuses them for self-built clients, so they are never contacted |
| `Online/OunsuMessagePackHubProtocol.cs` (new), `Online/HubClientConnector.cs` | SignalR's "messagepack" hub protocol without runtime code generation (`OUNSU_HUBS`). The stock one serialises each argument through `MessagePackSerializer.Serialize(Type, ref writer, ...)`, which throws under NativeAOT. Port of ASP.NET Core's MessagePackHubProtocolWorker (MIT) plus `OunsuHubTypes`, the list of types that may cross the wire (the metadata hub's). Byte-identical to the stock protocol (console/osu-game `OUNSU_HUB_SELFTEST`, `probes/hub-probe`) |
| `Online/PersistentEndpointClientConnector.cs` | Reconnect brake for hub connectors: connections that end within a minute add 15 s, 1 min, 4 min, 10 min before the next attempt, and after 6 in a row the connector stops. Upstream resets its back-off on every connect, so an accepted-then-dropped connection would be re-made every ~3 s |
| `Online/Metadata/OnlineMetadataClient.cs` | ppy's server pushes updates to a self-built client on this hub but refuses every call it makes ("Realtime online functionality is not supported on this version of the game"). The first call of a connection is a probe; once refused, nothing more is sent on that connection and no notification is raised. Not worked around |
| `Database/ModelDownloader.cs` | At most two downloads (download + import) at a time; more overlapping downloads froze the console in GC storms. Also gentle on ppy's servers |
| `Screens/Play/SubmittingPlayer.cs` | No score submission token request (always refused for self-built clients; it showed "Score will not be submitted" every play). `OUNSU_SUBMIT=1` asks anyway |
| `Database/ImportTask.cs` | Archives are opened with a 1 MiB read buffer: every read is a syscall the host answers from the SD card, and fewer, larger reads are much faster than the 4 KiB default |
| `Online/Notifications/WebSocket/WebSocketNotificationsClientConnector.cs` | Throws a real exception when the endpoint request fails (no network) instead of dereferencing the null response. Upstream relies on the NullReferenceException being caught; on the console a null dereference is a CPU fault that ends the process (no signals turn it into an exception) |

Not in this patch but required: the console app's assembly version is `0.0.0` (`console/osu-game/osu-game.csproj`), like
osu.Desktop built from source. With the default 1.0.0, osu! considered itself a deployed release, which sent API
version 10000 (the server then answered in an old format) and enabled Sentry crash reports to ppy.

Score submission is refused by ppy's server for self-built clients. That's by design, and this patch doesn't work around it.
